# 标准指标释义收进仓库级词典

## 状态

已接受，2026-08-03。

## 背景

`CONTEXT.md` 把标准指标定义为「具有稳定标识和**统一含义**的财务或资本指标，可在口径兼容时用于跨期间、跨公司比较」。

实际状况与这个定义相去甚远：`observationSchema.metricId` 是 `z.string().min(1)`，任何字符串都能通过；schema 里没有任何释义字段；释义确实写好了，但是在 `docs/research/metric-playbook.md` 里，以散文形式存在，读者在页面上看不到，机器也读不到。

于是「统一含义」全靠作者记性。两家公司可以各自给 `gross-margin` 赋予不同含义而校验器毫无反应——这恰好是该概念存在的目的所要排除的情况。

另一侧是驱动指标：`CONTEXT.md` 要求它「必须携带**公司适用的**定义」，schema 也确实有 `definition`/`causalRole`/`baseline`/`threshold`。这一层不需要改。

真实的例外是行业。`metric-playbook.md` 自己写了「银行/信贷……不用普通 FCF 估值」「金融企业不用此通式」。银行、保险、REIT 的 ROIC 与 FCF 口径确实不同。

## 决策

标准指标的释义放进 `packages/research-schema/src/metric-dictionary.ts`，全仓库一份。每条包含：一句话定义、算式、为什么重要、以及陷阱（哪些行业不适用）。

`metricId` 收紧为词典键的枚举。要用新指标就得先往词典里加一条，那是一个可评审的动作。

快照可选填 `standardMetrics[].definitionNote`，**追加**公司特定说明，不覆盖词典条目。云音乐的「无资本化开发成本，因此 FCF = OCF − PPE」属于这一类。

页面上，释义通过原生 `popover` 的 ⓘ 按钮呈现：默认不外露，需要时一点即开，零 JavaScript（发布物必须能从文件系统直接打开，见 `analysis-template.md` 的验收条款）。打印时浮层无法展开，改由页尾一份屏幕隐藏的「指标释义」定义表承担。

`metric-playbook.md` 仍然是方法论正文；词典是它的机器可读投影。两者冲突时以词典为准，要改的是散文。

## 备选方案

**纯词典，不允许任何覆盖。** 最纯粹，跨公司含义绝对一致。否决原因：银行遇到不适用的指标就只能另建 `bank-*` 系列 ID，词典会随行业膨胀，且「该用哪个 ID」变成新的判断负担。追加式的 `definitionNote` 保留了统一含义，同时容纳了真实存在的行业差异。

**每份快照自带 `definition` 必填字段。** 与驱动指标做法一致，不引入新概念。否决原因：直接违背 `CONTEXT.md` 对标准指标的定义；同一个「毛利率」在五家公司会有五种写法；且每新增一家公司都要重写十几条本来一模一样的释义。

**`title` 属性做提示。** 实现最省。否决原因：移动端完全不可触发，屏幕阅读器支持差，不能排版——而这个页面很可能就是在手机上看的。

## 后果

- 新增一个标准指标需要改代码。这是刻意的：标准指标的集合本来就该缓慢变化。
- 词典成了必须维护的资产。它的规模由「有多少个真正跨公司通用的指标」决定，而不是由公司数决定。
- 页面第一次能回答「这个数字是怎么算的、什么时候会骗人」，而不需要读者去翻方法论文档。
