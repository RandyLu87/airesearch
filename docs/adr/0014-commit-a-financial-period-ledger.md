# 每家公司提交一份财报期间账本

## 状态

已接受，2026-08-03。

## 背景

公司研究主页需要展示按报告期展开的财务对比，报告页需要最近两年的多期数据。落到取数上，三个市场的处境完全不同：

| 市场 | 合并三表 | 分部收入 | 可脚本化 |
| --- | --- | --- | --- |
| 美股 | SEC `companyfacts` XBRL，免费无鉴权 | companyfacts 只有公司层面，分部需解析维度化 XBRL 实例 | 三表可以，分部半自动 |
| A 股 | Tushare `income`/`balancesheet`/`cashflow` | `fina_mainbz` 主营构成直接给 | 需 `TUSHARE_TOKEN`，当前未配置 |
| 港股 | **无免费结构化源** | **只能从年报/中报 PDF 提取** | 否 |

港股是本仓库当前唯一有结构化快照的市场。核实结果：`hk_income` 文档明写「需单独开权限」（约 15000 积分 ≈ ¥1500/年），且返回 `ind_name`/`ind_value` 长格式而非规整三表；ADR-0013 与 `AGENTS.md` 已定「港股三表以年报和业绩公告原文为准，Tushare 仅作交叉核对」，因此付费买来的也只能当副证。搜索未找到 HKEX 已强制 iXBRL 的证据。stockanalysis.com 有半年度序列，但其 H2 是用全年减 H1 算出来的，且不含分部收入，按登记表 §6 只能交叉核对。

结论：**港股这份数据无论如何都要人工取一次。**

而 `data-source-registry.md` §7 要求「每次研究创建新的数据包，不把上次缓存默认为最新」，输出写入已被 gitignore 的 `tmp/`。对一份从 PDF 里手抠出来的历史序列，这条规则的实际效果是每次研究重抠一遍。

规模感：港股一家公司两年 = 2 年报 + 2 中报；美股 = 2 年报 + 8 季报。若这些全部按「骨架不继承数值」逐期哨兵化重填，作者负担直接压垮流程。

## 决策

每家公司提交一份 `research/companies/<company-id>/financials.json`，保存已披露报告期的规范数据，**一次取数、长期复用**。

账本不是第二事实源。研究快照仍然内嵌自己的 `financialHistory`，保持自包含与可哈希——ADR-0006 与 ADR-0009 依赖这一点。三处施力保证两者不漂移：

- `npm run snapshot:new` 从账本物化 `financialHistory`，作者不手抄；
- `npm run snapshot:sync` 随时重新物化；
- `npm run snapshot:check` 逐字段比对，不一致即失败。

**一致性只约束每家公司的当前快照。** 发行人重列往年数据时，账本前移、下一份快照吸收；已发布的带日期快照保留它当时写下的数字，因为 ADR-0002 让那些记录不可覆盖。若对全部历史快照强制一致，任何一次重列都会让整个仓库进入无正确解的失败态。

账本对新公司的最低覆盖是**最近两个完整年度**（上市不足两年则自上市起全部）。这正是主页一次同口径对比与报告页两年多期表实际消费的量。已有的更早期间保留不删。

期间带 `status`：`reported` 表示发行人自己披露过，`calculated` 表示由其他披露值推算（例如全年减中报得出的下半年）。读者必须能区分。

从账本预填数值不违反「骨架不继承数值」原则。那条规则防的是把上一次的**判断**当成本次结论；一个已收官的会计期间是披露事实，不是判断。

## 备选方案

**账本作为唯一事实源，快照只存引用。** 零重复，结构上不可能不一致。否决原因：快照不再自包含，发布物的 SHA-256 必须同时锚两个哈希，ADR-0006、ADR-0009 与发布测试都要改；更严重的是重列会追溯改写历史报告里的数字，直接违反 ADR-0002。

**继续只用 `tmp/` 缓存，延长 TTL。** 零架构变更。否决原因：`tmp/` 已被 gitignore，换机器、清理一次或新开一个会话就没了，而港股那些期间是人工从 PDF 抠出来的。它不解决问题。

**购买 Tushare 港股权限。** 否决原因见上：贵、只能当副证、且不含分部收入。ADR-0013 定下的重估触发条件（研究 A 股、跟踪公司数上升）仍然有效；A 股 profile 的价值明显高于港股。

## 后果

- 新公司入库多一步：先建账本，再生成快照骨架。这一步换来的是此后每次研究都不用重新取数。
- 账本是提交进 Git 的派生数据。它的正当性来自「取数昂贵且结果不可变」，不适用于行情、估值或任何判断类数据。
- `validate_research_paths.py` 会对有快照却无账本的公司目录报错，把「取不到就不给发布」的约束放在仓库级校验器上，而不是每一份合成快照上。
- 分部收入现在有了固定住处。它此前根本无处安放，只能塞进叙述文字。
