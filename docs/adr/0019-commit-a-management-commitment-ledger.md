# 每家公司提交一份管理层承诺台账

## 状态

已接受，2026-08-05。实现排期见 GitHub Issue。

## 背景

治理与资本配置目前全部是横截面判断：

| 现有机制 | 它看的是 |
| --- | --- |
| `WORKFLOW.md:69-70` 治理评价（执行能力、控制权、少数股东保护、股权激励、资本配置） | 当期的判断，落点是 `sections` 散文 |
| `red-flags.md:43-45`「回购发生在明显高估区」「派息或回购长期超过自由现金流」 | 当期的回购价与当期的覆盖情况 |
| `metric-playbook.md:22` 股东回报覆盖率 = 股息与净回购 ÷ FCF | 当期比值 |

缺的是纵向记录：管理层三年前说过什么，做到了没有。这件事无法从任何一期的财务数据里读出来，只能靠逐条累积。

**它为什么不能是快照字段。** 一条 2024 年 Q4 电话会上的承诺，可能到 2026 年才结算。若把它放进快照，每次研究都要把三年的承诺重新抄一遍。`snapshot:new` 的「不继承数值」规则防的是把上次的判断当本次结论，而这里的问题正相反：一份不可变的历史行为记录，每次重抄的成本会压垮作者，实际结果是每次只写最近一条，累积价值为零。

**它和 `financials.json` 同构。** 取数昂贵（要翻三年电话会记录、股东信与公告）、结果不可变（说过的话不会变）、一次录入长期复用。ADR-0014 已经为这个形状定下先例，包括「提交进 Git 的派生数据，正当性来自取数昂贵且结果不可变」这条正当性论证。

**它和 `checkpoints` 不是同一个对象。** `checkpoints` 是研究者声明的下一期可证伪阈值，可以随时修改——改了不损失任何东西。承诺是公司的历史行为记录，一旦录入不可改写；改写就毁掉了兑现记录的全部意义。可改写性不同的两个对象不该合并。

对照参考实现（`ai-berkshire/skills/management-deep-dive.md:74-158`）：承诺 vs 兑现追踪表、并购逐笔事后回报、回购时机与当时 PE、新业务投入回报。机制是对的，但它保存在一份每次重新生成的 Markdown 里，因此实际上不累积。

## 决策

每家公司提交一份 `research/companies/<company-id>/commitments.json`，追加式，提交进 Git。

一条记录用 `kind` 区分两类事实：

- `承诺` —— 管理层说过的、可判定的话；
- `并购` / `回购` / `分红` / `新业务投入` —— 管理层做过的、有事后结算的资本配置动作。

| 字段 | 要求 |
| --- | --- |
| `id` | 稳定 ID |
| `kind` | 上述五值 |
| `statedAt` | 说出或执行的日期 |
| `venue` | 场合：年报 / 中报 / 业绩发布会 / 股东信 / 公开采访 / 公告 |
| `quote` | 原文摘录，不转述 |
| `commitment` | 可判定的承诺内容或动作描述——「持续提升股东回报」不是可判定的，不录 |
| `dueBy` | 到期时点，允许 `未给时限` |
| `status` | `兑现` / `部分兑现` / `未兑现` / `待到期` / `已撤回` |
| `resolvedAt` | 结算日期 |
| `outcome` | 结算依据。只写状态字不合格 |
| `evidence` | 至少一条指向原文；结算时再加一条指向结算依据 |

`并购` 与 `回购` 条目额外记录金额、当时的估值口径与事后回报评估——这把 `red-flags.md:43`「回购发生在明显高估区」从印象变成可复算的记录：每笔回购留下当时的估值口径，与今天的价值区间可以直接对照。

**物化与校验沿用 ADR-0014 的三处施力。** `npm run snapshot:sync` 从台账物化一份摘要进快照（未兑现与部分兑现清单、按 `kind` 的计数比例、最近一次结算），`npm run snapshot:check` 逐字段比对，作者不得手写。一致性只约束该公司的当前快照，已发布快照按发布时的数字冻结——理由与 ADR-0014 第 35 行完全相同。

**明确不做的两件事。**

不把兑现率映射成评语档位。参考实现把兑现率分成「>80% 优秀 / 60-80% 合格 / 40-60% 令人担忧 / <40% 严重问题」四档（`management-deep-dive.md:85-90`）。计数比例是事实，档位是判断，而这个判断的分母完全取决于录入了哪些承诺——写成档位，会让一个可以靠「少录几条软承诺」操纵的数字看起来像一个评级。页面只呈现计数与未兑现清单。

不做加权综合评分（诚信 35% + 能力 25% + 资本配置 25% + 治理 15%，`management-deep-dive.md:250-256`）。理由同 `business-model-playbook.md:70`：四个不可比维度的加权和不携带比它的分项更多的信息，只是把判断藏进权重里。

## 备选方案

**只做快照内的 `governance.capitalAllocation[]`，每次重写。** 不新增账本与 sync 链路，改动最小。否决原因：跨期承诺无法累积。三年历史每次重抄，实际结果是只写最近一条，于是这个字段回答不了它唯一想回答的问题。

**扩展 `financials.json`，增加一个 commitments 段。** 少一本账本。否决原因：财报账本按报告期组织，受 `ledger.ts` 的期间排序契约管辖（`analysis-template.md:133` 那条字典序要求）。承诺按「说出时点 + 到期时点」两个时间轴组织，塞进去要么破坏期间排序，要么需要一套并行结构。两本账本各自内聚更便宜。

**只写一份管理层方法论手册，产出仍归 `sections`。** 零契约成本。否决原因：手册能教怎么提取承诺，不能让承诺留下来。（手册仍然要写，见 `docs/research/management-playbook.md`；它是台账的录入方法，不是台账的替代品。）

**不做。** 否决原因：现有机制全是横截面的，而「说到做到」只能纵向观察。这是当前框架里唯一一个连观察工具都没有的治理维度。

## 后果

- 新公司入库多一步：建承诺台账。与 ADR-0014 建财报账本同一性质的一次性成本，首次录入覆盖最近三年。
- `validate_research_paths.py` 不对缺台账报错——一家刚上市的公司可能确实没有可录入的承诺。但**空台账必须显式存在并写明覆盖起始时点**：「没有承诺」和「没查」必须能区分，而这个区分只有显式空文件能表达。
- 台账是提交进 Git 的派生数据，正当性同 ADR-0014。它对判断类数据不适用——而 `status` 的判定本身就是判断，因此 `outcome` 必须写结算依据并附证据，不能只写一个状态字。
- 页面新增治理区块，呈现未兑现清单与逐笔资本配置记录。回购时机因此第一次可复算。
- 台账不追溯改写。发行人事后重述过的指引按新增条目处理，并在 `outcome` 里指明它替换了哪一条——ADR-0002 的不可覆盖原则同样适用于管理层说过的话。
