# 每一组估值假设都署名到外部来源，并逐席声明该来源的偏向

## 状态

已接受，2026-08-05。取代 ADR-0017 的三情景模型；与 ADR-0021 同批落地。

## 背景

ADR-0021 删掉了立场与合理价值，但没有解决估值假设从哪来的问题。反向估值要解出「当前价格隐含 `dc-segment-margin` 需站上 35%」，必须把其他所有变量钉在某个值上——而 1.1.0 里那些钉住的值是作者写的：

```ts
scenarios: z.array(z.object({
  name: z.enum(["熊市", "基准", "牛市"]),   // ← 写死的三档
  ...
})).length(3)
```

`基准` 这个词做了两件事。它在算术里是「拿来算 `summary.fairValue` 的那一档」，在阅读上是「作者认为最可能的未来」。第二个含义没有任何字段承载，也没有任何来源支撑，但它决定了页面上哪一根柱子被高亮、哪一个区间被当作答案。

`valuation.disagreement.ourAssumption` 把这件事写在了字段名里。分歧永远是「我 vs 市场」，读者除了信或不信我，没有第三条路。

同时存在一个反向的问题：**有些来源是可引用的，但页面把它们渲染得同样中立。** 一份做空报告的假设组合和一份发行人指引，在 HTML 里是同一种字体。做空报告的作者持有空头仓位；发行人指引由发行人自报；卖方与发行人普遍存在承销与研究付费关系。不写出来，「多视角」就变成借别人的嘴表达倾向。

## 决策

**`valuation.scenarios` 换成 `valuation.assumptionSets`：每一席署名到本仓库以外的一份文件，并逐席必填 `sourceBias`。**

```
sourceKind    发行人指引 / 卖方一致预期 / 历史区间回归 / 做空报告 /
              监管与政策文件 / 同业公开指引 / 其他
sourceNote    仅当 sourceKind 取「其他」时必填，写明这一组究竟出自哪里
sourceLabel   具体是谁、什么时候
sourceBias    该来源的已知偏向，无例外必填
status        available | unavailable（后者必写 reason，且不得携带任何数字）
components    与 1.1.0 相同的组件模型
```

`disagreement` 相应改形：`ourAssumption` → `referenceAssumption` + `assumptionSetId`，`ifMarketIsRight` → `divergenceLink`。两端于是都可引用——一端由价格反解，一端由发行人或卖方公开说出，差值是算术。校验器强制 `assumptionSetId` 命中一个 `available` 席位：对照一个取不到的席位等于跟沉默比较。

`impliedExpectation` 从 valuation 顶层移进每一席，反向估值对每组各解一次。

### 席位没有下限

骨架给三个起点（发行人指引、卖方一致预期、历史区间回归），但它们不是必须凑满的格子：港股与 A 股没有已登记的一致预期源，很多公司明确不提供指引，而有做空报告或监管听证的公司可以加到五席六席。

引擎只要求**至少一组 `available`**。这不是一个判断门槛而是一个算术门槛：一组都算不出来时，价格隐含没有任何可对照的数字，估值块也就没有内容。实践中「历史区间回归」只依赖 `financials.json`，任何有账本的公司都能算——所以算不出来通常意味着没算。

### 为什么偏向逐席必填

一个只在「可疑来源」上出现的偏向字段，本身就是一个判断：谁可疑由作者决定，而作者已经被禁止做价格类判断。逐席必填把这个决定拿掉——发行人指引也要写「自报，历史上下限偏保守」，历史区间回归也要写「隐含假设未来仍在同一机制内，机制已变时系统性偏低」。

### 席位的跨快照延续

`thesisChange.assumptionSetChanges` 照搬 `driverChanges` 的机制，记 `added` / `removed` / `redefined` 与理由，校验器强制，只在两份都是 1.2.0 的快照之间执行。同一个 id 换了 `sourceKind` 或 `sourceLabel` 算 `redefined`——跨快照的数值对比会因此不再指同一件事。

席位既然没有下限，这条记录就是「这一组不再存在」与「这次没查」唯一的区分手段。空台账必须显式存在这条原则（ADR-0019）在这里再用一次。

## 备选方案

**保留熊/基准/牛，只删 `summary.fairValue` 与 `actionZones`。** 工作量最小，无引擎改动。否决原因：「基准情景」三个字仍然在告诉读者哪个未来最可能，而那正是要去掉的东西。删掉输出但留下带偏向的输入，等于把判断藏进标签。

**允许作者补一组自建假设集，标为 `sourceKind: "本研究"` 并计入证据密度的推断占比。** 保留了灵活性，缺数据的公司不至于无席可用。否决原因：那一席会成为默认路径——它永远可得，而外部来源需要去取。便宜的那条路必须堵住，`evidenceDensity` 的设计理由（ADR-0020）同样适用。

**整块删除估值，只留当前倍数与历史分位。** 最中立。否决原因：反向估值与分歧点一起死掉，而它们是「价格隐含什么」这个问题唯一的答案形式，也是 ADR-0021 换掉研究第三问之后的全部内容。

**额外席位必须成对（引一个偏空的就必须引一个偏多的）。** 对称最硬。否决原因：常常有一边根本不存在，强制配对会逼出编造，而这与整套契约的第一原则直接冲突。

## 后果

- 首次研究一家新公司多出一项取证工作：三类来源各自去哪里取、取不到时把 reason 写清楚。这是刻意的，缺口从此可见。
- 页面上没有任何一席被高亮，图表也不再强调任何一条柱子——被强调的那条就是被推荐的那条。
- 跨公司的席位数量会不一致（AMD 可能六席，茅台可能两席）。这是数据可得性的事实，不做拉平；`sourceBias` 与 `unavailable` 的 reason 让读者能看出差异从哪来。
- `deriveActionZones` 与 `verifyPriorValuation` 保留，仅用于校验冻结的 1.1.0 快照，见 ADR-0021。
- 熊/基准/牛之间的单调性检查删除：署名席位之间没有应该成立的顺序，发行人指引落在做空报告之上是信息，不是不一致。
