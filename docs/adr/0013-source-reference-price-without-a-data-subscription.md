# 参考价格用可引用公开源取证，暂不购买行情订阅

## 状态

已接受，2026-08-03。

## 背景

`data-source-registry.md` 把 Tushare 列为港股的固定结构化路径，同时禁止「固化网页内部未公开接口或反向工程参数」。但仓库里唯一一份带价格的研究快照（网易云音乐 2026-07-31）把 `summary.referencePrice` 记为来自腾讯行情接口 `https://qt.gtimg.cn/q=hk09899`——正是被禁的那一类源。

也就是说：**登记表禁掉了唯一实际可用的源，却没有给出合法替代。** 结果是上一次研究违规使用，下一次研究被卡住。

2026-08-03 尝试更新网易云音乐时，这个缺口第一次造成实际阻断：

- `TUSHARE_TOKEN` 未配置，登记的结构化路径不可用；
- HKEX 官方报价页抓取返回空模板，不可机读；
- 公司 IR 站 TLS 证书签给 `web002.guruir.com`，机器抓取失败；
- Yahoo Finance 返回无日期的陈旧价，与其他源偏离 6.5% 且涨跌方向相反。

同时查证了 Tushare 定价（<https://tushare.pro/document/1?doc_id=290>）：120 分免费但仅限未复权日线、50 次/月；2000 分 ¥200/年；**港股与美股是独立权限模块，需在基础积分之上单独授权，¥200–2,000/年**。

关键观察：每次研究真正必须的只有**一个带时间戳的参考价格**，不是一条行情流。三表与财务指标的权威来源本来就是年报和业绩公告——登记表自己就写明「API 不替代原始财报、公告和附注」。为「每次研究取一个数」支付年费不成比例。

## 决策

**不购买行情订阅。** 参考价格改为显式取证输入：允许任何可公开访问、可引用、带明确时间戳的源，但必须双源交叉、必须建立 `evidence` 记录（`publisher` / `url` / `retrievedAt` / `caveat`）、且取价过程不得写进 `scripts/`。

同时把登记表里那条禁令的适用范围写清楚：它约束的是**脚本化的批量结构化取数**（固化会无声失效、可能违反服务条款、且规模化调用），不约束一次性、人工核对、带证据记录的单点取价。这解决了登记表的自相矛盾，而不是简单地放宽它。

取不到可靠价格时中止研究，不允许估算——参考价格会一路传导进合理价值、安全边际和行动区间。

现有 schema 无需改动：`summary.referencePrice` 的 `value`/`currency`/`asOf` 加上 `evidence` 的 `url`/`retrievedAt`/`caveat` 已经完整支持这一模式，2026-07-31 快照事实上就是这么记录的。

## 备选方案

**购买 Tushare 港股权限（¥200–2,000/年）。** 否决原因：付费换来的主要是三表与历史行情，而三表的权威来源本就是原始公告；真正的日常缺口只有一个价格。**若未来需求扩大——需要批量历史日线画决策图表、开始研究 A 股、跟踪公司数量上升到人工取证不现实、或跨公司横向比较成为瓶颈——应重新评估，且 A 股 profile 的价值明显高于港股**（`api-catalog.json` 的 a profile 覆盖日线、估值、三表、财务指标、主营构成与分红，是三个 profile 中最宽的）。

**券商 OpenAPI（Longbridge / Futu）。** Longbridge 的 HK LV1 基础行情免费，但 Quote API 需单独开通 OpenAPI 行情权限；Futu 需要本地或云端常驻 OpenD 网关并走自定义 TCP 协议。两者都要券商账户，对「每次研究取一个数」的场景过重，且引入了一个必须长期运维的依赖。

**AkShare 等开源封装。** 免费，但本质是包装同一批未公开网页接口，等于把违规洗一遍而不是解决它。

**只用 HKEX 官方源。** 最正当，但实测其报价页不可机读，无法作为唯一路径。

## 后果

- 取价需要人工双源核对，比调 API 慢，但每次研究只做一次。
- 源的可用性会漂移。登记表里新增了一张「已核实源状况」表，失效时就地更新，避免每次重新踩坑。
- 腾讯接口的使用从「违反登记表」变成「登记表明确许可的人工取证路径」。这是承认既成事实，同时给它套上双源交叉与证据记录的约束——而不是默许。
- 港股三表在获得 Tushare 授权前，以年报与业绩公告原文为准，不做 API 交叉核对。
