# 估值方法选择与落地

本文件回答三个问题：市场上有哪些估值方法族、这家公司该用哪一种、用不上最理想那种时该补什么信息。可执行定义以 `packages/research-schema/src/valuation/` 为准；本文件与代码冲突时以代码为准。

**这份文件不产出「这家公司值多少钱」。** 1.2.0 契约不发布合理价值、立场、安全边际或操作区间（ADR-0021）。估值算术保留，因为它是让假设变得明确、可复算、可被下一份财报判定的唯一手段；变的是它的朗读方向——不是「公司值 X，所以当前价贵了」，而是「这一组署名假设对应 X，当前价格在同一个指标上隐含 Y」。两个数字都摆出来，读者自己减。

## 1. 方法族总览

| 族 | 方法 | 什么时候是最优解 | 必需输入 | 引擎支持 |
| --- | --- | --- | --- | --- |
| 内在价值 | FCFF 折现 | 现金流可预测、再投资路径清晰 | 多年收入与利润率路径、税率、再投资、WACC、终值 | 仅交叉验证 |
| | 股利折现 DDM | 分红稳定、派息率可预测 | 股利路径、派息率、股权成本 | 仅交叉验证 |
| | 剩余收益 RIM | 账面价值有经济含义（银行） | 期初账面价值、ROE 路径、股权成本 | 仅交叉验证 |
| 相对估值 | 正常化 P/E | 盈利稳定、资本结构简单 | 正常化归母净利润区间、倍数区间、股数、汇率 | 引擎计算 |
| | EV/EBIT | 资本结构差异大 | EBIT 区间、倍数区间、净债务 | 引擎计算 |
| | EV/Sales | 未盈利或利润率剧烈变化 | 收入区间、倍数区间、净债务 | 引擎计算 |
| | P/B | 银行、保险、重资产 | 归母净资产、倍数区间、ROE 路径 | 引擎计算 |
| 资产 | NAV / RNAV | 控股公司、地产、资源 | 资产逐项重估值、负债、折价依据 | 引擎计算 |
| 加总 | **SOTP 分部加总** | 混合业务、分部走势相反、大额非核心资产 | 各分部经营利润与倍数、非核心资产面值与折价 | 引擎计算 |
| 反向 | 当前价隐含预期 | **所有公司都要做** | 参考价格、股数、汇率、主方法盈利口径 | 引擎计算 |

行业特定倍数（EV/ARR、P/AFFO、P/EV、EV/储量）用相应族的组件表达，在 `metricLabel` 中写清分子口径。

## 2. 选择顺序

1. **先看非经营资产占比。** 净现金、投资组合、可变现土地占市值超过 30% 时，任何合并倍数法都在用错误的方式给这笔资产定价，必须把它单列。
2. **再看业务是否同质。** 分部走势相反、或存在实质不同的商业模式时，合并盈利的「正常化」没有经济含义。
3. **再看盈利是否代表稳态。** 连续盈利不足三年、处在周期顶点或谷底、含大额一次性项目时，单年倍数不可靠。
4. **最后看行业禁忌。** 银行与保险不用普通 FCF 和 EV 口径；周期股不用单年峰值盈利。

体检规则把这四步固化成可自动触发的判断，见下一节。

## 3. 体检规则

规则从财报账本与快照自身事实计算，触发后作者必须在 `valuation.healthCheck` 中逐条回应。回应有四种：

- `adopted` —— 采纳规则建议，换了方法或加了处理；
- `blocked` —— 认可规则成立，但缺数据做不到，必须在 `methodSelection.blockedBy` 中列出缺口；
- `rejected` —— 不采纳，必须说明为什么这条规则在本公司不适用；
- `acknowledged` —— 已在别处（风险、约束、折价）反映，不改变方法。

某条规则不建议把某方法当主方法，而作者把它标为 `adopted` 时校验器报错——采纳建议却没换方法是自相矛盾。

当前规则集见 `rules.ts`：大额净现金、净负债偏重、盈利历史不足、当期亏损、自由现金流为负、分部走势相反、业务高度集中于单一分部、股东回报薄弱且现金堆积、客户集中、金融企业、周期性行业。

任何情况下都强制：至少一条交叉验证方法，以及当前价格的隐含预期。

## 4. 组件模型

一个情景由若干组件相加减构成，引擎负责算术：

```
倍数项   value = 指标区间 × 倍数区间
面值项   value = 金额 × (1 − 折价%)
每股价值 = Σ(±组件) ÷ 汇率 ÷ 股数
```

区间算术按方向取值：总额下沿取所有加项的下沿与所有减项的上沿。写反了会让区间变窄，而变窄总是更好看的方向，所以这一步由引擎做而不是由作者做。

三种典型配置：

- **合并倍数法**：一条倍数项。注意口径自洽——若正常化盈利里仍含现金利息收入，就不能再加净现金面值项，否则同一笔钱计两次。
- **SOTP**：每个分部一条倍数项，非核心资产一条面值项，治理折价写在面值项的 `discountPct` 上并给出 `discountReason`。
- **银行 P/B**：一条以净资产为指标的倍数项。

`valuation.shares.scale` 必须等于 `valueScale`，全部组件金额也用同一 scale。汇率是「报告币种 / 交易币种」，必须双源交叉并建立至少两条 evidence。

组件属于**某一组假设集**，不属于某个情景。同一家公司的三组假设集通常用同一套组件结构，只是指标区间不同——发行人指引给一个利润区间，一致预期给另一个，历史区间回归给第三个。结构相同、数字不同，正是它们可以并列比较的前提。

## 5. 缺口与升级

`methodSelection` 同时记录 `ideal` 与 `adoptedPrimary`。两者不同时，`blockedBy` 每一项写明：

| 字段 | 要求 |
| --- | --- |
| `dataItem` | 缺的是什么，具体到可去取的一个数 |
| `whyNeeded` | 它为什么能解锁理想方法 |
| `whereToGet` | 去哪份文件的哪一部分取 |

这份清单直接渲染在页面上。它的作用是让「本次估值不够好」成为一条有行动项的记录，而不是一句免责声明。写「需要更多数据」这种话不算合格。

## 6. 反向估值

引擎对**每一组 available 的假设集**各反解一次：持有该组全部面值项不动，用当前市值解出倍数项隐含的倍数。

它回答的是「市场在假设什么」，不是「值多少钱」，不能单独作为估值结论。但它是最容易发现自己算错的一步——若隐含倍数与自己给的基准倍数差得离谱，通常是汇率、股数或口径出了问题，而不是市场疯了。

非经营资产占比高时，`impliedExpectation.nonOperatingPerShare` 已经把「扣掉非经营资产后市场给经营业务多少钱」单独算出来了，页面直接呈现，这往往比合并倍数更能说明问题。

### 分歧点

隐含倍数给出的是市场的数字，不是市场的理由。反向估值算完之后必须再走一步：**说清分歧落在哪个驱动上，以及两种读法在因果链哪一环分道扬镳。**

| 要写的 | 要求 |
| --- | --- |
| `driverId` | 必须是一个已声明的 `driverMetrics[].id`。「竞争加剧」「监管风险」这类不落在任何指标上的说法不算——它们对任何公司在任何价格都成立，因此不解释任何具体的价差 |
| `assumptionSetId` | 拿哪一组署名假设集做对照，必须命中一个 `status: "available"` 的席位。对照一个取不到的席位等于跟沉默比较 |
| `marketAssumption` | 按隐含倍数反推，当前价格在这个驱动上隐含了什么路径 |
| `referenceAssumption` | 该署名来源在同一驱动上假设了什么路径 |
| `divergenceLink` | 两者在因果链哪一环分开，以及下一期哪个观测值会先判定 |
| `converged` | 两者几乎重合时置真，并如实写重合 |

强制锚在驱动上是这一步的全部意义：它让「价格和这份指引不一致」变成「价格和这份指引在哪一个可观测量上不一致」，而后者可以被下一份财报判定。

**两边都是别人的数字。** 旧契约这一栏写的是「我的假设」，于是分歧永远是「我 vs 市场」，读者除了信或不信我没有第三条路。换成署名假设集之后，比较的两端都可引用：一端是价格反解出来的，一端是发行人或卖方公开说的，差值是算术。

## 7. 署名假设集

`valuation.assumptionSets` 取代了旧契约的熊市/基准/牛市。区别不在数量，在**假设从哪里来**：「基准」是作者认为最可能的那个未来，而署名假设集的每一组都指回本仓库以外的一份文件。

每个席位必填：

| 字段 | 要求 |
| --- | --- |
| `sourceKind` | 发行人指引 / 卖方一致预期 / 历史区间回归 / 做空报告 / 监管与政策文件 / 同业公开指引 / 其他（取「其他」必须写 `sourceNote`） |
| `sourceLabel` | 具体是谁、什么时候。「公司 FY2025 年度业绩发布会」而不是「公司指引」 |
| `sourceBias` | 该来源的已知偏向。**无例外必填** |
| `status` | `available` 或 `unavailable`；后者必须写 `reason`，且不得携带任何数字 |
| `components` | 与第 4 节相同的组件模型，`available` 时必填 |
| `evidenceIds` | `available` 时至少一条。署名到外部来源才算署名 |

### 为什么每一席都要写偏向

做空报告的作者持有空头仓位，发行人指引由发行人自报，卖方与发行人普遍存在承销与研究付费关系。这些不是可疑，是常态——但一个把它们渲染成同一种字体的页面，等于借别人的嘴表达倾向。偏向字段在每一席上都必填而不是只在「可疑来源」上必填：只在某些席位出现的偏向字段，本身就是一个判断。

### 席位没有下限

三类默认席位（发行人指引、卖方一致预期、历史区间回归）只是骨架给的起点，不是必须凑满的格子。港股与 A 股没有已登记的一致预期源，很多公司明确不提供指引——这些席位标 `unavailable` 并写明 reason，让「没有这一组」和「没有查」能区分。反过来，有做空报告、监管听证、同业指引的公司可以加到五席六席。

引擎只要求**至少一组 available**：一组都算不出来时，价格隐含没有任何可对照的数字。实践中「历史区间回归」只依赖 `financials.json`，任何有账本的公司都能算出来，所以这条门槛不构成阻碍——算不出来通常意味着没算。

### 席位跨快照的延续

`snapshot:new` 继承上一份快照的席位 id 与 `sourceKind`，重新索取其余一切。增删席位或让同一个 id 换了来源，必须在 `thesisChange.assumptionSetChanges` 中记 `added` / `removed` / `redefined` 与理由，校验器强制——席位没有下限，所以没有这条记录时「这一组不再存在」和「这次没查」完全一样。
