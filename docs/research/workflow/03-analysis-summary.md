# 分析总结（研究流程第 3 步）

本文件是 `docs/research/public-company-financial-research.md` 第 3 步的唯一正文。基于第 1 步采集的数据与第 2 步各维度分析的结果，由评估 Agent 给出六个维度的结论总结与信心度评分，并对四类主要策略给出专业建议。

- **输入**：第 1 步采集文件（`financials—model-template.json` 结构）+ 第 2 步分析文件（`financials—analysis-template.json` 结构）。
- **产出**：按 `docs/model/financials—summary-template.json` 结构生成总结文件，落盘为 `research/companies/<company-id>/financials-summary.json`（文件名固定，渲染层按名发现）。

## 执行方式

**使用 Task 工具启动一个独立评估 Agent**（Codex 端用可用的子代理能力等价执行）。给评估 Agent 的指令必须包含前两步落盘文件的完整内容与统一输出格式（即汇总模板结构）。

评估 Agent 的职责边界：

- **只基于前两步已落盘的数据与分析做评估，不重新采集**。发现某维度证据不足时，不补采数据，而是降低该维度信心度并在 `scoreBasis` 中写明缺口；
- 每个结论、每个评分、每条策略建议都必须能指回第 2 步分析文件的具体字段或第 1 步的具体数据点，不接受凭空判断。

## 维度结论与信心度评分

对以下六个维度逐一给出**结论总结**与**信心度评分**（映射第 2 步的六个分析维度）：

| 维度 | 对应第 2 步维度 | 结论 | 信心度（0-10） |
|------|----------------|------|---------------|
| 生意质量 | businessEssence | | |
| 护城河 | moat | | |
| 管理层 | management | | |
| 最大风险 | inversion | | |
| 文明趋势 | industryTrend | | |
| 估值 | valuation | | |

**评分规则（总分 10 分）**：

- 信心度反映**证据密度与数据质量**，不是看多程度——一个证据充分的负面结论同样可以得高分；
- 打分依据（`scoreBasis`）必须引用第 2 步分析文件的具体字段与数据；
- 参考梯度：9–10 关键数据双源验证充分、追问有数据支撑的回答；7–8 主体数据完整、仅局部缺口；5–6 关键数据部分缺失或依赖推断；3–4 大量依赖估计值；0–2 数据不足以支撑任何结论；
- 该维度 `dataGaps` 越多、`[估计]` 值占比越高，信心度越低，两者的对应关系要在 `scoreBasis` 中写明。

## 策略建议

对四类主要策略分别给出**专业建议**：

| 策略 | 面向 |
|------|------|
| 空仓者 | 尚未持有该公司的投资者 |
| 持仓者 | 已持有该公司的投资者 |
| 卖出信号 | 什么情况下应当卖出 |
| 加仓信号 | 什么情况下可以加仓 |

建议的硬性要求：

1. 每条建议必须**绑定可观察的触发条件**——价格区间、基本面指标阈值或具体事件，不允许「视情况而定」「保持关注」这类无法执行的表述；
2. 价格类触发条件必须引用第 2 步估值维度的三情景计算结果（`threeScenario`）；
3. 基本面类触发条件必须引用第 2 步的失败路径（`failurePaths`）、护城河 breaker 或驱动指标，做到「信号出现时能立刻识别」；
4. 建议与信心度联动：信心度低的维度不得作为策略建议的主要依据，若引用必须注明其信心度。

## 硬性输出要求

1. 六个维度的结论、评分、打分依据齐全，评分为 0–10 的整数或 0.5 步长的数值；
2. 四类策略建议齐全，且每条都有可观察触发条件；
3. 所有结论与建议均可追溯到前两步落盘文件的具体字段（`basis` 字段写明引用路径）；
4. 汇总结果按 `docs/model/financials—summary-template.json` 落盘到 `research/companies/<company-id>/`；
5. 文末保留免责声明：分析基于公开信息与截止时点数据，不构成个性化投资建议。

## 完成标准

六个维度的结论与信心度评分齐全且依据可追溯；四类策略建议齐全且触发条件可观察、可执行；引用的价格与阈值均来自前两步经工具验算的数字；数据截止时间已声明。
