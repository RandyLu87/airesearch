# 分析总结（研究流程第 3 步）

本文件是 `docs/research/public-company-financial-research.md` 第 3 步的唯一正文。基于第 1 步采集的数据与第 2 步各维度分析的结果，由评估 Agent 给出七个维度的结论总结与信心度评分，并对四类主要策略给出专业建议。

- **输入**：第 1 步采集文件 `research/companies/<company-id>/financials-collection.json`（`financials—model-template.json` 结构，可能含 Evidence Agent 补写的 `evidenceAppendix`）+ 第 2 步分析文件 `research/companies/<company-id>/financials-analysis.json`（`financials—analysis-template.json` 结构）。
- **产出**：按 `docs/model/financials—summary-template.json` 结构生成总结文件，落盘为 `research/companies/<company-id>/financials-summary.json`（文件名固定，渲染层按名发现）。

## 执行方式

**使用 Task 工具启动一个独立评估 Agent**（Codex 端用可用的子代理能力等价执行）。给评估 Agent 的指令必须包含前两步落盘文件的完整内容与统一输出格式（即汇总模板结构）。

评估 Agent 的职责边界：

- **只基于前两步已落盘的数据与分析做评估，不重新采集**。发现某维度证据不足时，不补采数据，而是降低该维度信心度并在 `scoreBasis` 中写明缺口；
- **不产生新的 `evidenceRequest`、不触发新一轮取证**——第 2 步最多 2 轮的取证流程已经是证据获取的终点（见 `02-multi-dimension-analysis.md`「第二步联网规则」），本步骤只对已定型的数据与分析做评估；
- 每个结论、每个评分、每条策略建议都必须能指回第 2 步分析文件的具体字段或第 1 步的具体数据点，不接受凭空判断。

## 维度结论与信心度评分

对以下七个维度逐一给出**结论总结**与**信心度评分**（前六个映射第 2 步的六个分析维度，企业文化映射管理层维度的 `analysis.culture` 子字段及管理层维度相关证据）：

| 维度 | 对应第 2 步维度 | 结论 | 信心度（0-10） |
|------|----------------|------|---------------|
| 生意质量 | businessEssence | | |
| 护城河 | moat | | |
| 管理层 | management | | |
| 最大风险 | inversion | | |
| 文明趋势 | industryTrend | | |
| 估值 | valuation | | |
| 企业文化 | management.analysis.culture | | |

**评分规则（总分 10 分）**：

- 信心度是**价值投资视角下对该维度的看多程度**——按巴菲特/芒格/段永平式的标准，衡量该维度对长期股东有多有利，分数越高越看多；
- 各维度的评分语义：**生意质量**=这门生意本身有多好（单位经济、现金创造、经营杠杆）；**护城河**=有多宽、多耐久；**管理层**=能力、资本配置纪律与股东利益一致性有多强；**最大风险**=风险有多可控——风险越致命、越不可对冲，分数越低；**文明趋势**=长期趋势对公司有多有利；**估值**=当前价格相对内在价值有多有吸引力——越低估分越高，价格透支越严重分越低；**企业文化**=文化对长期股东有多有利（诚信与披露质量、长期主义、股东导向、组织与人才稳定为正；粉饰、短期激进、高管动荡为负）；
- **企业文化维度的结论是客观陈述，不是印象分**：只转述第 2 步 `dimensions.management.analysis.culture` 及管理层维度其他字段（`keyDecisions`、`alignment`、`organization`）已落盘的可观察证据，不引入前两步文件之外的公司口碑、媒体印象或行业刻板印象，严禁编造。该字段缺失、为 `unavailable` 或证据以单源/`[估计]` 为主时，结论如实写明证据限制，信心度向中性（5–6）收敛；
- 参考梯度：9–10 教科书级优秀（宽护城河 / 卓越管理层 / 显著低估这类特征）；7–8 明显有利、有小瑕疵；5–6 中性或好坏参半；3–4 明显不利；0–2 严重不利（如护城河不存在、估值严重透支、致命且不可控的风险）；
- 打分依据（`scoreBasis`）必须引用第 2 步分析文件的具体字段与数据，写清「为什么看多/看空到这个程度」；
- **证据不足不等于利空**：该维度 `dataGaps` 多、`[估计]` 值占比高、或结论主要依赖 `evidenceAppendix` 中**未做双源交叉验证的单源补充事实**（Evidence Agent 因检索预算限制只取到一个来源）时，评分同样向中性（5–6）收敛并在 `scoreBasis` 写明证据限制，不把数据缺口或未双源验证的补充事实误当作已验证的确定事实推高信心度。

## 策略建议

对四类主要策略分别给出**专业建议**：

| 策略 | 面向 |
|------|------|
| 空仓者 | 尚未持有该公司的投资者 |
| 持仓者 | 已持有该公司的投资者 |
| 卖出信号 | 什么情况下应当卖出 |
| 加仓信号 | 什么情况下可以加仓 |

建议的硬性要求：

1. 每条建议必须**绑定可观察的触发条件**——价格区间、基本面指标阈值或具体事件，不允许「视情况而定」「保持关注」这类无法执行的表述；
2. `advice`、`condition`、`signal`、`observable` 正文写给读者，用人话与具体数字，**不夹带字段路径**（如 `dimensions.xxx.yyy`）；字段路径只出现在 `basis` 里；
3. 价格类触发条件必须引用第 2 步估值维度的三情景计算结果（`threeScenario`）；
4. 基本面类触发条件必须引用第 2 步的失败路径（`failurePaths`）、护城河 breaker 或驱动指标，做到「信号出现时能立刻识别」；
5. 建议与信心度自洽：估值维度评分低（价格透支）时不得给出追买类建议，生意/护城河评分低时不得以「长期逻辑」为由建议死扛；某维度评分主要建立在 `[估计]` 值或单源数据上时，引用它的触发条件必须要求多源确认。

## 输出格式与篇幅

格式规则与第 2 步同源，完整说明见 `docs/research/workflow/02-multi-dimension-analysis.md`「返回形式（硬约束）」与「字段写法：分点 + 篇幅上限」两节，这里只列本步骤的差异与字段上限。

**返回形式**：评估 Agent 只返回一个 JSON 代码块，块外不写任何文字；结构与 `docs/model/financials—summary-template.json` 逐字段一致（不新增、不删、不改名），无法给出的字段写 `{ "status": "unavailable", "reason": "…" }`；返回内容必须能被 `json.loads` 直接解析。

**分点**：叙述字段超过约 2 句 / 80 字，用 `"① …。② …。③ …。"`（或句末标点后的 `1)`）分点，每点一件事、60 字内。网页端按 `apps/web/app/companies/[company]/page.tsx` 的 `splitPoints` 把每点断成独立一行；字符串里不写 Markdown（`#`/`**`/`-`/表格竖线会原样漏到页面上）。模板里定义为字符串的字段不要改成数组——渲染层遇到数组只输出「—」。

| 字段 | 篇幅上限 |
|------|---------|
| `dimensionSummary[].conclusion` | 1–3 句 / 100 字，不分点（渲染在窄卡片里，分点会把卡片抽高） |
| `dimensionSummary[].scoreBasis` | 2–4 点 / 合计 240 字 |
| `strategies.*.advice` | 2–3 点 / 合计 180 字 |
| `condition` / `action` / `signal` / `observable` | 单句 40 字，不分点（各自渲染成一行，长了会挤掉阈值数字） |
| `basis` | 2–3 点 / 合计 180 字，引用的字段路径写在点内 |
| `disclaimer` | 保持模板原文，不改写 |

超上限的处理与第 2 步一致：先看是不是两点在讲同一件事（该并），或者一条建议塞了多个触发条件（该拆成多个 `triggers` / `signals` 元素），而不是硬删字数。

## 硬性输出要求

1. 七个维度的结论、评分、打分依据齐全，评分为 0–10 的整数或 0.5 步长的数值；企业文化维度的结论为客观陈述且全部可追溯到已落盘证据；
2. 四类策略建议齐全，且每条都有可观察触发条件；
3. 所有结论与建议均可追溯到前两步落盘文件的具体字段（`basis` 字段写明引用路径）；
4. 返回满足「输出格式与篇幅」一节：单个 JSON 代码块、字段名与模板一致、超长叙述用 `①②③` 分点、各字段不超篇幅上限、字符串内无 Markdown；
5. 汇总结果按 `docs/model/financials—summary-template.json` 落盘到 `research/companies/<company-id>/`；
6. 文末保留免责声明：分析基于公开信息与截止时点数据，不构成个性化投资建议。

## 完成标准

七个维度的结论与信心度评分齐全且依据可追溯（企业文化为客观陈述、无落盘证据之外的内容）；四类策略建议齐全且触发条件可观察、可执行；返回通过格式验收（JSON 可解析、字段名与模板一致、超长叙述已分点、字段未超篇幅上限）；引用的价格与阈值均来自前两步经工具验算的数字；数据截止时间已声明。
