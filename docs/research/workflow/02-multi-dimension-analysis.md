# 多维度分析（研究流程第 2 步）

本文件是 `docs/research/public-company-financial-research.md` 第 2 步的唯一正文。在第 1 步采集产出的基础上，对六个维度分别做深入分析，汇总为一份结构化数据文件。

- **输入**：第 1 步落盘的采集文件（`docs/model/financials—model-template.json` 结构）。
- **产出**：按 `docs/model/financials—analysis-template.json` 结构生成分析文件，落盘为 `research/companies/<company-id>/financials-analysis.json`（文件名固定，渲染层按名发现）。

## 执行方式

**每个维度使用 Task 工具启动一个独立后台 Agent**（六个 Agent 可并行；Codex 端用可用的子代理能力等价执行）。给每个 Agent 的指令必须包含：

1. 第 1 步采集文件的相关内容（或其摘要）作为基础材料；
2. 数据截止时间与本维度的分析要点、追问；
3. 统一输出格式（见下节）——不接受自由体裁的返回。

Agent 职责：在第 1 步数据基础上**继续网络搜索补充材料**（同行数据、历史类比、空方观点、卖方与媒体报道等第 1 步清单之外的信息），完成本维度分析。每条分析必须带数据与来源（名称 + URL + 时点），无出处的论断不接受。

主会话职责：汇总六个维度的返回，检查格式统一、追问已答；凡涉及计算的数字（估值倍数、情景推算、增速、对比差值）一律用 `docs/research/tools/financial_rigor.py` 验算，禁止 LLM 心算，工具输出记入 `crossValidationLog`；最后按模板落盘。

## 统一输出格式

六个维度共用同一信封（与 `docs/model/financials—analysis-template.json` 对应），Agent 必须按此返回：

- `conclusion`：一句话结论，必须能被下方数据支撑；
- `analysis`：本维度专属字段（见各维度定义）；
- `inquiry`：`{ question, answer }`——**追问必须有回答**，只有在关键数据确实缺失时才允许答「数据不足」，且要写明缺哪个数据；
- `dataGaps`：缺失项 + 缺失原因 + 已查范围。

图表类内容（收入结构、趋势线）以结构化数据序列表达，渲染留给发布环节。

## 维度一：生意本质

分析要点：

- 用一句话定义这门生意的本质
- 收入结构拆解（结构化序列）
- 5年盈利能力趋势（结构化序列）
- 商业模式画布：一次性销售 vs 订阅/复购？硬件 vs 软件 vs 平台？
- 生态粘性/客户锁定强度
- 毛利率水平与同行对比，解释为什么高/低
- 经营杠杆分析

**追问**：这门生意好在哪？如果只能用一句话描述，是什么？

## 维度二：护城河评估

逐一验证五类护城河：

| 护城河类型 | 验证方法 |
|-----------|---------|
| 品牌/定价权 | 是否能在不损失销量的情况下提价？ |
| 转换成本 | 客户迁移到竞品的成本有多高？ |
| 网络效应 | 用户越多产品越好吗？ |
| 规模效应 | 规模带来的成本优势有多大？ |
| 技术/专利壁垒 | 技术领先几年？能否被复制？ |

分析护城河趋势：过去5年变宽还是变窄？未来5年预判。

**追问**：10年后这条护城河还在吗？什么能摧毁它？

## 维度三：逆向思考与风险清单

- 列出「这家公司可能失败的所有路径」（路径/概率/影响程度）
- 历史类比：找到历史上处于相似位置的公司，结局如何？
- 跨学科分析：用网络效应理论、技术采纳曲线、竞争博弈等模型交叉验证
- 偏误自查：叙事偏差、锚定效应、幸存者偏差
- 收集空方核心论点

**追问**：我最可能在哪里犯错？聪明人为什么会不买/做空这家公司？

## 维度四：管理层评估

- CEO/创始人关键决策复盘（时间/决策/结果/评分）
- 资本配置能力：研发回报率、并购成功率、回购时机
- 股东利益一致性：管理层持股、薪酬结构、减持记录
- 组织能力：团队稳定性、关键人才风险
- 企业文化特征

**追问**：如果CEO退休，这家公司还能保持竞争力吗？

## 维度五：行业与长期趋势

- 判断所在行业是否处于「文明级范式转移」
- 历史技术革命类比（蒸汽机/电力/互联网/AI）
- TAM增长曲线与天花板分析
- 公司在产业价值链中的位置
- 技术路线风险
- 客户/供应商集中度分析

**追问**：站在20年后回看，这家公司是「这个时代的标准石油」还是「昙花一现的3Com」？

## 维度六：估值分析

- 当前市场定价（关键估值指标）——**必须通过工具验算**
- 反向DCF：当前股价隐含了什么增长预期？
- 三情景估值——**必须通过工具精确计算，禁止心算**：

```bash
python3 docs/research/tools/financial_rigor.py three-scenario \
  --price {股价} --eps {EPS} --shares {总股本亿} \
  --growth {乐观增速} {中性增速} {悲观增速} \
  --pe {乐观PE} {中性PE} {悲观PE} --years 3 --currency {币种}
```

- 与自身历史估值对比
- 与同行估值对比

**追问**：如果股市明天关闭5年，你愿意以这个价格持有吗？

## 硬性输出要求

1. **所有分析必须有数据支撑，附数据来源**（名称 + URL + 时点），估计值标注 `[估计]`；
2. **追问部分必须有回答**，回避视为该维度未完成；
3. 六个维度输出格式统一，均使用上述信封结构；
4. 分析结果汇总成结构化数据，按 `docs/model/financials—analysis-template.json` 落盘到 `research/companies/<company-id>/`；
5. 涉及计算的数字必须经 `docs/research/tools/financial_rigor.py` 验算，工具输出记入 `crossValidationLog`（规则沿用第 1 步）。

## 完成标准

六个维度全部返回且格式统一；每个 `conclusion` 都有 `analysis` 内的数据与来源支撑；追问全部有回答；估值维度的每个数字都经工具验算；`dataGaps` 中的缺失项写明原因与已查范围。
