# 来源优先级与核验

## 优先级

1. 监管机构与交易所原始文件：SEC、HKEX、上交所、深交所等。
2. 公司投资者关系：经审计年报、中报、业绩公告、演示文稿、正式电话会材料。
3. 法定文件：招股书、通函、投票结果、权益披露、薪酬与可持续发展报告。
4. 公司业务材料：产品文档、定价、招聘、开发者文档、客户案例；只用于验证产品和组织，不替代财务披露。
5. 权威行业资料、竞争对手正式文件和政府数据。
6. 市场数据商用于价格、汇率和交叉检查；媒体、社交平台和员工评价只作线索。

## 最低核验步骤

1. 核对法律实体、股票代码、报告期、发布日期、币种、单位和合并范围。
2. 记录“信息发布日期”和“市场价格时间”，特别说明收市后公告。
3. 优先使用报告正文和附注，不只读取演示材料中的调整后数字。
4. 核对基本与摊薄 EPS、法定与非公认会计指标、原始与重列数据。
5. 财务表、分部表、现金流表和管理层解释相互交叉验证。
6. 冲突时采用监管/交易所文件，并解释公司演示或数据商为何不同。

## 每次评估的最新信息扫描

不论用户是否明确要求“最新”，每次都联网扫描到执行时点，并记录绝对截止时间。至少检查：

1. 监管机构/交易所的最新定期报告、临时公告、权益披露、融资、回购、并购分拆与治理文件。
2. 公司 IR 的最新业绩材料、指引、电话会、产品/定价/客户/渠道/产能公告和管理层变动。
3. 上次研究截止日后的重要行业、监管、诉讼、供应链和技术事件。
4. 主要竞争对手的正式披露，用于验证需求、价格、份额、成本或技术替代；不要用竞争对手叙事直接推定本公司数据。
5. 当前或最近收盘股价、币种、时间戳和公告前后关系。

对网页和消息同时记录 `event_date` 与 `publish_date`；发布日期不等于事件发生日。新闻优先追溯到公告、法院/监管文件、产品页或当事方声明。找不到一手材料时，可用多个可信来源交叉验证，并标明尚未由公司或监管机构确认。

把新信息映射到商业模式驱动树，不输出孤立新闻列表：它影响的是客户需求、获客、供给、定价、单位经济、再投资、护城河还是关键依赖？说明它是短期参数变化、机制变化或结构性变化。若没有新披露，写明检索范围和“截至该时点未发现足以改变判断的新证据”。

## 来源日志字段

| 字段 | 要求 |
| --- | --- |
| source_type | 交易所/监管/公司IR/行业/市场数据 |
| document_title | 正式文件名 |
| period_end_date | YYYY-MM-DD |
| publish_date | YYYY-MM-DD HH:MM TZ（可得时） |
| event_date | YYYY-MM-DD（与发布日期不同时单列） |
| url | 直接原始链接，不用搜索结果页 |
| fields_extracted | 使用了哪些数字或事实 |
| driver_mapping | 映射到哪个商业模式环节或核心指标 |
| caveat | 口径、重列、时点、确认状态或可靠性限制 |

## 特殊取证

- **人员职能**：优先年报附注、ESG、招股书、薪酬分部；招聘和 LinkedIn 只能辅助确定范围。
- **研发投入**：同时查损益表、费用附注、员工成本、政府补贴、资本化开发费用和无形资产添置。
- **客户集中**：查主要客户收入、应收集中度和地区收入；中期未更新时明确沿用的年度数据。
- **分拆/重组**：必须查交易所公告、通函、股东大会、SEC/上市文件，不用媒体标题代替条款。
- **当前价格**：记录交易所、币种、时间戳及盘中/收盘状态；价格晚于财报发布才视为已反映信息。
- **产品、定价和渠道**：优先公司产品页、价目表、开发者文档、门店/渠道公告和客户合同；保存发布日期或网页抓取时间，区分试点与全面落地。
- **竞争与行业**：优先竞争对手正式文件、监管/政府数据和权威行业统计；媒体用于发现事件和补充现场信息，不替代公司特定 KPI。
